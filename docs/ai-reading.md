# 原文对照与 AI 阅读助手

更新日期：2026-10-13。

## 阅读与排版

“原文＋覆盖译文”和“译文覆盖”共用固定页框与字体适配逻辑。两侧页框高度、起点、原栏宽一致，不以拉长页面推动后续图像或段落。右侧保留图表与公式原件画面；特别长的译文在段落内滚动，也可双击或使用“查看本段”读取完整对照。详见 [排版规范](layout-alignment.md)。

译文保留原有的列表编号、分点、首行缩进、悬挂缩进和可识别的嵌套缩进。普通视觉换行在同一条目内合并，不把每行误认作一个新段落。存量译文只在原编号仍存在且能按顺序匹配时重建分点；缺失编号会提示，不猜测缺失的译文。源文字行框、原件、标注和解析修订不因显示修复而改变。

## 目录

优先使用有效的 PDF 自带书签；只有一个论文标题的书签时回退到正文章节。编号与标题分块时按同一行、字号和间距拼合。图内标签、表格指标和正文词语经过语义与区域筛选，不凭短、粗体或大写进入目录。新导入的医学扩散论文和 CodecLM 的正文及附录标题均已核对。

## AI 操作

1. 点击“AI 阅读助手”，输入问题并发送，或按 Ctrl+Enter；三个快捷问题面向整篇文献，点击后切换到“范围：整篇文献”并清除旧选区，只填入文本，不自动发送。之后仍可手动调整取文范围。
2. 在原文、译文或完整段落中划词后，可解释术语、公式或提出具体问题。图片中的公式没有可提取文字时，不能宣称已自动识别。
3. 回答流式出现；“停止”或关闭助手会停止接收并断开上游连接。已经收到的内容保留，服务是否已处理及实际计费不能据此保证。
4. 可选“依据当前文献”或“文献＋通用知识”。点击回答下方来源按钮回到对应页和段落；未知来源编号会提示。
   “取文范围”单独控制自动判断、整篇文献或所选内容；它与是否允许通用知识是两个不同设置。
5. 已确认的 Ollama 云端兼容接口可提交默认、低、中、高思考强度。其他兼容服务使用默认，不盲发扩展参数。这个强度是请求设置，不是模型实际思考质量或完成百分比。
6. 阶段显示来自真实响应：连接模型、观察到思考输出、生成公开依据摘要、输出回答。界面展示真实耗时；服务提供思考 token 用量时才展示该数值。
7. “回答依据摘要”是模型在正式输出中生成的最多两句简短证据与方法说明，可折叠查看。它不是内部思维链；原始 reasoning_content 等思考文本不会写入 SSE、浏览器或对话历史，也不用于拼凑假的推理记录。

思考参数的能力与具体等级由服务及模型决定，参考 [Ollama 兼容协议](https://docs.ollama.com/api/openai-compatibility) 和 [思考能力文档](https://docs.ollama.com/capabilities/thinking)。

## 服务、上下文与历史

复用翻译设置的地址、模型、密钥及环境变量规则，不另建一套密钥。一次主动提问最多发送 8 段原文、18000 字符上下文、每段 2500 字符，选中文字最多 6000 字符、问题最多 2000 字符，最近有效对话最多 8 条消息。不会无界发送全文。

检索是关键词与常见中文科研词扩展，不宣称向量语义检索。2026-10-13 修正概括上下文：自动模式下，“概括内容”“概括本文”等整体问题优先从摘要、引言、方法、结果、结论及文献不同位置选取正文；选中的标题不能获得全文概括优先权，也不能由一批章节标题占满来源。无法识别章节时采用有界的正文分布采样，不宣称发送了全文。

“这段／本段／所选内容”等局部概括以及术语/公式解释，在存在选区时优先所选块和同页上下文。普通相关问题至少保留可用正文来源，避免被标题挤占。用户显式选择整篇文献或所选内容可覆盖自动判断；无选区时选择“所选内容”会提示先选择。完整概括或全文检索遇到只有标题/非正文的修订，返回 `no_body_context`，先提示解析问题，不向模型发送一次缺失正文的请求。

流式 meta 与最终结果提供 `context_summary`，显示本次取文方式、正文条数及覆盖页数。来源均为节选，长块会标记截断。提示词要求以本次实际来源为准，避免沿用历史“只有标题”的误答；正文不足时应指出缺失的具体方面。来源可核对不代表模型解释自动正确。回答下方的来源严格对应本次提供的段落；引用未提供的 [S99] 等编号会提示。

对话仅在当前页面会话内存保存，最多保留 30 轮；刷新后清除。中断的部分回答不作为下一轮已完成的模型回答发送。离开文献页会取消正在接收的流，防止回答落到另一篇文献中。结果不写入翻译缓存或文献正文。

## 协议与失败处理

- 保留原同步回答接口；页面使用 POST `/documents/{id}/assistant/stream`，SSE 事件为 meta、phase、summary、delta、done、error。
- 配置和段落归属在接收流之前校验。后台数据库会话在向模型请求之前关闭。
- 上游使用异步 HTTP 流；浏览器停止、页面离开或断流时关闭响应资源。
- 浏览器按 UTF-8 增量解码，支持跨字节、跨行和跨 SSE 帧的中文内容；异常帧会取消读取。
- 只有 done 表示正式回答完整结束。达到长度上限或未正常结束会提示不完整；超时、断流、错误均不自动重试，避免重复请求和计费。
- 不支持流式协议的兼容服务明确报告错误，不以再次收费请求掩盖问题。

## 验收与边界

上下文修复增加了标题优先级、全文/局部范围、无正文拒绝及流式来源覆盖回归。在当前 Docker 文献的只读审计中，新的概括来源全部为正文，跨页取文；旧上下文在该样本也有部分正文，因此未把所有模型误答归因于单一检索缺陷。受控浏览器与接口验证真实发送的正文和范围显示，不把受控回答称为真实模型概括质量验收。证据见 [上下文修复验收](acceptance/2026-10-13/assistant-context/README.md)。

本轮后端 745 项通过，阅读器及浏览器流解析逻辑 22 项通过。隔离浏览器验证了真实 BrLP 原件副本的列表、目录、21 页几何、中文分块、摘要与来源、取消后关闭上游连接、窄屏布局；受控 AI 响应明确标记为界面验收样例。

另用当前真实配置对现有 CodecLM 文献执行一次实际提问。deepseek-v4.1-flash 返回 HTTP 200、50 个公开摘要增量、96 个回答增量和实际来源；客户端约 5.07 秒开始显示正式回答，总用时约 5.42 秒。仅一次请求，无自动重试。这个时长是本次观测，不保证后续延迟，也不代表科研结论质量已全面审核。

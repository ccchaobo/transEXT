# 完整文献聊天验收

用户明确要求所有提问统一使用整篇文章，包括标题和参考文献，不再按局部、当前页或关键词限制资料范围。本轮替换八块节选方案，所有有文字或结构化表格的块均按阅读顺序进入请求。长段落不裁剪，页眉页脚、参考文献及不可翻译的文字也保留。

全文状态接口与流式响应报告 `full_document`、`complete=true`、`excerpts=false` 及真实文字块、页和类型统计。旧范围字段仅用于接受旧客户端，不改变全文。超过本机 200 万字符保护上限时整体拒绝；服务明确拒绝上下文容量时报告专门错误，不改发节选或自动重试。只有标题的修订可用于标题信息提问，完全无文字才拒绝；图片像素尚不作为模型输入，提供已有文字、图注和表格结构。

助手界面采用文献卡、对话区和底部输入框。新对话与设置进入菜单，关注内容只标明问题主题；答案支持安全 Markdown、复制、行内引用和折叠来源。无需运行时 CDN，离线解析器固定为 markdown-it 15.0.2，包完整性与文件哈希已记录。

后端全套 764 项、前端 34 项通过，OpenAPI 64 schema、48 path 校验通过。新增回归覆盖完整来源、超过原八块/18000字符及长段落、参考文献/页眉/表格、原始文本回退、旧范围兼容、整体拒绝、服务容量错误与不重试，另有构建缓存固定版本保护检查。

受控 Chrome 21 项检查通过，见 [记录](browser-report.json)：七次实际请求逐字核对完整来源段、编号、顺序与文字，包含自编三页文献的二十个文字块；其中包含标题、参考文献与三个页脚。覆盖选中标题、三个预设、设置、Markdown 结构及 HTML 不执行、复制、来源折叠、窄屏、新对话、容量拒绝、停止和旧后端拒绝。停止后上游流关闭一次。没有外部 AI 调用。

界面截图见 [文献聊天](01-document-chat.png)、[设置](02-chat-settings.png)、[窄屏](03-chat-mobile.png)。代码和 HTML 片段为刻意编写的安全验收样例，不是用户论文，也不代表真实模型回答质量。只核实模型实际收到完整解析文字，不宣称未解析图像已经被理解。

当前实现规范见 [AI 阅读](../../../ai-reading.md)；整体视觉和交互见 [UI 规范](../../../ui-design.md)。本轮部署会核对镜像内资源及真实文献的解析修订、指纹与页数，记录仅含匿名检查结果，备份保留在本机。

## Docker 与实际实例

完整依赖重装曾在下载阶段遇到哈希不匹配，失败产物未启用，没有忽略哈希校验。将固定依赖与项目打包拆成独立缓存层后，复用此前可信镜像；构建核对目标 Python 可执行文件及全部固定版本，然后重新打包最终项目代码。最终镜像为 `sha256:a3147676c31ea6559440cf77f246c4bbc808e3736f44aa45989b664fdf98e4e0`，保存在 `research-reader:full-document-ui` 与 `research-reader:local`。

隔离 Compose 项目中 API、worker、GROBID 健康；真实 GROBID、OCR、中文渲染、格式限制和重建后持久化均通过，见 [功能检查](docker-functional-report.json)。全部 16 个前端文件及 4 个核心后端模块逐字节匹配验收源码，见 [镜像资源](image-source-check.json)。

实际使用的 API/worker 已更新，继续挂载原数据卷，GROBID 没有重新创建。升级前先生成本机一致性备份；升级后原文献标识、解析修订、原件指纹与页数保持一致。实际十页论文的完整输入包含 265 个文字块、47249 字符、7 个参考文献块及全部十页，未向付费模型发送请求。见 [上线核对](live-upgrade.json)。这里只验证可提取文字完整，不宣称图像像素也已输入模型。
